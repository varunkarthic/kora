# Rust vs. C++ (1.0)

KORA 1.0 is a rewrite, so it was measured against 0.3 on the same GPU before release: ten
ABBA-interleaved pairs of `kora-bench --gpu --cluster` per Vulkan driver on an Apple M4 (100 samples,
10 warm-ups per run). Charts and tables are generated by
[`tools/bench-report/render.py`](https://github.com/varunkarthic/kora/blob/main/tools/bench-report/render.py)
from the retained reports in and summaries are retained in
[`benchmarks/results/rust-vs-cpp-apple-m4`](https://github.com/varunkarthic/kora/tree/main/benchmarks/results/rust-vs-cpp-apple-m4).

!!! summary "In short"
    - **Faster in 1.0:** task-graph finalize and replay (~35%), allocators, staging-ring reservations
      (now constant-time in the number of live ranges), direct transfers.
    - **At parity:** every KORA dispatch family, default and deferred readback, and device times,
      within this machine's noise band of about ±10% per family.
    - **Slower:** Cluster local dispatch (+24% MoltenVK, +8% KosmicKrisp), the tiny-dispatch case
      (+5–12%), and SAXPY at 1M with default readback on MoltenVK. Host submission is equal or faster
      in 1.0; the remaining difference is in device completion and large host copies. Tracked in
      [#263](https://github.com/varunkarthic/kora/issues/263).

## How to read these

"Before" is C++ 0.3 (`e07fd51`) and "after" is Rust 1.0 (`f03431c`). A ratio below 1.00 means 1.0
is faster. `host_allocation_4k` is not comparable: the C++ compiler may elide that allocation. The
3–4× gap between KORA and raw Vulkan device time at 1M elements on MoltenVK
([#229](https://github.com/varunkarthic/kora/issues/229)) is the same in both builds.
